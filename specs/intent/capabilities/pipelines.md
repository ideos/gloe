# Pipeline contracts

- **CAP-PIPE-001:** One `Transformer[P, R]` composes ordinary typed functions, callable objects, bound methods, partials and other pipelines. Invocation is always awaited; `.sync(...)` blocks and rejects an already running event loop.
- **CAP-PIPE-002:** `gloe.input[T]()` anchors an explicit unary input; `gloe.input()` infers a concrete input from its first stage. Ambiguous generic or overloaded entry points require an explicit anchor. Composition checks every edge and branch and preserves exact tuple outputs.
- **CAP-PIPE-003:** `>>` creates a new immutable sequence and never executes a stage during construction. It never deduplicates executions. Tuple branches receive the same value, run concurrently and return in declaration order. Failure or cancellation cancels and awaits outstanding siblings.
- **CAP-PIPE-004:** `@gloe.transformer` creates a configuration factory. Positional parameters describe pipeline inputs; keyword-only parameters describe configuration. Calling the factory binds configuration and returns a callable with only its input signature. Ordinary functions require no decorator. Explicit variadic factories are rejected; ordinary variadic functions can still be composed when their signatures allow the incoming value.
- **CAP-PIPE-005:** Lowercase `map(callback)` and `filter(predicate)` factories accept sync or async callbacks and return ordered lists, consuming iterables sequentially. Filter requires actual booleans and preserves supported predicate narrowing. `condition(predicate, then=..., otherwise=...)` selects exactly one branch. `parallel(callables)` and `sequential(callables)` support homogeneous dynamic branches.
- **CAP-PIPE-006:** A tuple is one value; `unpack(fn)` explicitly adapts a tuple to multiple positional arguments. Zero/multiple input roots can use `Transformer(fn)`. No implicit tuple spreading.
- **CAP-PIPE-007:** `@ensure(incoming=..., outcome=..., changes=...)` retains the function signature and checks its unary data input, resolved output, or their pair. Validators are synchronous, return None or raise, and can be supplied individually or as tuples/lists. Checks fail before later effects. Configuration is excluded from the data contract. Before values are references, not automatic deep copies.
- **CAP-PIPE-008:** Retaining early data uses a fork and join: `prefix >> (input(), work) >> unpack(finish)`. Prefix execution occurs once per invocation; intermediate work receives only its own input. Pipelines contain no invocation-specific shared storage. Calling `pipe2 >> pipe3` runs both complete sequences, even if their definitions share a prefix.
- **CAP-PIPE-009:** Graph inspection/export reflects sequential and branched structure without running business functions. Repeated occurrences remain distinct. Graphs describe dependencies, not inferred purity or caching.
